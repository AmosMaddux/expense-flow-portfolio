# Service Evidence Packets

The service evidence packet workflow is generated by
`.github/workflows/service-evidence-packets.yml` on every push. It uploads one
CI-built evidence artifact for Core Case Service and one for GL-coding service.
Frontend evidence is intentionally out of scope for this workflow.

## Packet contents

`manifest.json` is the authoritative map from evidence artifact to the gate
that produced it.

### Core Case Service

| Artifact                                | Producing gate                       |
| --------------------------------------- | ------------------------------------ |
| `test-output/typescript-vitest.txt`     | TypeScript Vitest tests              |
| `test-output/python-pytest.txt`         | Python pytest tests                  |
| `coverage/typescript/`                  | TypeScript Vitest coverage           |
| `coverage/python/`                      | Python pytest coverage               |
| `security/semgrep-report.json`          | Semgrep source SAST gate             |
| `security/bandit-report.json`           | Bandit Python SAST gate              |
| `security/trivy-report.json`            | Trivy image vulnerability gate       |
| `security/sbom.cdx.json`                | Syft SBOM generation                 |
| `signing/cosign-sign-image.txt`         | Cosign image signing                 |
| `signing/cosign-attest-sbom.txt`        | Cosign SBOM attestation              |
| `signing/cosign-verify-image.txt`       | Cosign image signature verification  |
| `signing/cosign-verify-attestation.txt` | Cosign SBOM attestation verification |
| `reproduce-tagged-build.md`             | Evidence packet assembler            |

### GL-coding Service

| Artifact                                | Producing gate                       |
| --------------------------------------- | ------------------------------------ |
| `test-output/python-pytest.txt`         | Python pytest tests                  |
| `test-output/provider-pact.txt`         | GL-coding provider Pact              |
| `coverage/python/`                      | Python pytest coverage               |
| `security/bandit-report.json`           | Bandit Python SAST gate              |
| `security/trivy-report.json`            | Trivy image vulnerability gate       |
| `security/sbom.cdx.json`                | Syft SBOM generation                 |
| `signing/cosign-sign-image.txt`         | Cosign image signing                 |
| `signing/cosign-attest-sbom.txt`        | Cosign SBOM attestation              |
| `signing/cosign-verify-image.txt`       | Cosign image signature verification  |
| `signing/cosign-verify-attestation.txt` | Cosign SBOM attestation verification |
| `reproduce-tagged-build.md`             | Evidence packet assembler            |

Cosign signatures and SBOM attestations are registry-bound records attached to
the pushed GHCR evidence images. Each packet stores the image reference, digest
when resolved, and command output proving that CI verified both records.

## Reproducing a tagged Core Case build

1. Fetch tags from source control: `git fetch --tags origin`.
2. Check out the tagged source: `git checkout <tag>`.
3. Install Node dependencies from the lockfile: `npm ci`.
4. Install Python dependencies from the lockfile: `uv sync --frozen`.
5. Run Core Case TypeScript tests and coverage:
   `npm run build && npx vitest run --coverage --coverage.thresholds.branches=0 --coverage.thresholds.functions=0 --coverage.thresholds.lines=0 --coverage.thresholds.statements=0 --project unit --project integration --project production --exclude backend/core-case-service/src/glCoding/glCodingClient.pact.test.ts --passWithNoTests`.
6. Run Python tests and coverage:
   `UV_CACHE_DIR=/tmp/expense-flow-uv-cache uv run pytest --cov=backend --cov=evaluation --cov-report=term --cov-report=xml:coverage/python/coverage.xml --cov-report=html:coverage/python/html`.
7. Build the Core Case Service image:
   `docker build --file backend/core-case-service/Dockerfile --tag core-case-service:<tag> .`.
8. Scan the image with Trivy, generate the Syft CycloneDX SBOM, push the image
   to a registry, sign it with Cosign, attest the SBOM, then verify the image
   signature and attestation with the same identity constraints recorded in
   the CI workflow.

## Reproducing a tagged GL-coding build

1. Fetch tags from source control: `git fetch --tags origin`.
2. Check out the tagged source: `git checkout <tag>`.
3. Install Node dependencies from the lockfile: `npm ci`.
4. Install Python dependencies from the lockfile: `uv sync --frozen`.
5. Run GL-coding tests and coverage:
   `UV_CACHE_DIR=/tmp/expense-flow-uv-cache uv run pytest tests/test_auth_jwt.py tests/test_expense_line_item.py tests/test_gl_coding.py tests/test_gl_coding_contract.py tests/test_gl_mapping_repository.py tests/test_service_health.py --cov=backend/python --cov-report=term --cov-report=xml:coverage/gl-coding-service/python/coverage.xml --cov-report=html:coverage/gl-coding-service/python/html`.
6. Run provider Pact verification:
   `UV_CACHE_DIR=/tmp/expense-flow-uv-cache uv run pytest tests/test_gl_coding_provider_pact.py`.
7. Build the GL-coding service image:
   `docker build --file backend/python/Dockerfile --tag gl-coding-service:<tag> .`.
8. Scan the image with Trivy, generate the Syft CycloneDX SBOM, push the image
   to a registry, sign it with Cosign, attest the SBOM, then verify the image
   signature and attestation with the same identity constraints recorded in
   the CI workflow.
